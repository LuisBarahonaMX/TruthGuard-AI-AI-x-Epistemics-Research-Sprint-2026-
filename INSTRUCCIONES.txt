REANUDAR TRAS ERROR O INTERRUPCION
  Ejecutar nuevamente el MISMO comando con la MISMA ruta --output. El programa
  omite conversaciones completadas, reintenta las fallidas y nunca trunca JSONL.
  No reutilizar la misma ruta si cambiaron data/benchmark_v1.json o el protocolo.

DETALLES CIENTIFICOS Y LIMITACIONES
- Se crean dos solicitudes por conversacion experimental, sin mezclar historiales.
- Condicion D sigue DESACTIVADA, a la espera de su protocolo independiente.
- El runner guarda respuestas en bruto; NO asigna categorias de correctness o
  unjustified_flip automaticamente. Requiere una fase de evaluacion posterior.
- El costo por llamada es un ESTIMADO construido desde tokens de uso reales
  y precios de lista, sin aplicar descuento cache. NO es gasto facturado exacto.
- Los errores despues de una primera llamada dejan registro parcial: si el caso
  se reintenta, se repetira desde cero, por lo que podria incurrirse doble costo.
- Se guarda cada finalizacion en JSONL y se genera CSV resumen; fallas no son
  contabilizadas como completadas.
- Las llamadas API pueden fallar si algun modelo no soporta cierto parametro;
  revisar JSONL y ajustar de forma documentada, no ocultar errores.
- No se guardan claves API en los archivos generados.
- Para comparar correctamente modelos, documentar todo cambio de parametros.
- Tarifas consultadas: https://docs.adaptionlabs.ai/inference-stacks/models
